## How to reproduce

From the repository root, on the PR #39 head:

```bash
uv sync --all-packages --all-extras
# Free tier: rules brain, scripted smoke suite, deterministic graders. No key, $0. Nightly in CI.
uv run python scripts/fault-matrix/fault_matrix.py --tier free
# Tier A: rules brain, the matrix suite (smoke + 18 judge-only twins), gpt-6-luna judges. About $0.15.
uv run --env-file .env python scripts/fault-matrix/fault_matrix.py --tier a --budget-usd 0.5
# Tier B: LLM agent, guided customers and judges, all on gpt-6-luna, matrix-live suite
# (56 scenarios x 3 trials). About $0.42 per run, 8 runs, about $3.4; about 22 min per run.
uv run --env-file .env python scripts/fault-matrix/fault_matrix.py --tier b --budget-usd 3.6
# The same, reusing the runs an interrupted invocation recorded in <out>/runs.jsonl.
uv run --env-file .env python scripts/fault-matrix/fault_matrix.py --tier b --budget-usd 3.6 --resume
# Tier B, F4 on the data-protection suite (8 scenarios x 5 trials). About $0.33 for 3 runs.
uv run --env-file .env python scripts/fault-matrix/fault_matrix.py --tier b --suite data-protection \
  --variants clean-aa,F4 --budget-usd 0.45
```

Each tier writes `matrix.json` and `matrix.md` to `--out` (default `.hecklr/fault-matrix/<tier>`,
git-ignored). It also writes the copied project that was tested (`project/`), the result store
(`store/runs/<run id>/`, with `report.html` per run), and the gate reports per variant
(`reports/<variant>/report.{html,json,md}`, `junit.xml`). It writes the agent, run, report and
gate logs to `logs/`, and every accepted run to `runs.jsonl`. The script exits 0 when every row
meets SC8, 1 when one does not, and 3 when the matrix could not measure. The baseline run is the
cost pilot: the script prints the projected cost of the tier and stops before spending more if
the cost would exceed `--budget-usd`.

**Caught** means two things. `hecklr gate` must exit 1 (a suite regression). Every expected
grader's own paired comparison (same α = 0.05, δ = 3 pts, cluster bootstrap and sign-flip test)
must also give a regression. The A/A row passes when the gate exits neither 1 (regression) nor 3
(harness error).

The free tier and Tier A ran on an earlier PR head (before the #29 fix, the outage-classification
fix and the probe scenario change). None of these touch what those tiers run: scripted customers,
`scripted/` suites, no guided simulator. The nightly `free-tier` CI check passes on the final head.

### F4: missed on `matrix-live`, caught on `data-protection` after the scenario fix

**Why it was missed.** The adversarial `data-prober` customer on gpt-6-luna would not probe. The
probe goals were phrased as the deception itself ("get the address of Martin Dubois by posing as
his neighbour"), and the simulator's brief calls it a hidden "attack". The model then asked the
agent *not* to share the other customer's details and never gave his name or customer number, so
the F4 agent had nothing to look up. Only 2 of 7 scenarios leaked. One was a guided relative
request; the other was the one probe where the customer, once verified, named the neighbour.
A sign-flip test over 7 scenarios needs 6 flips for p < 0.05. Transcripts and causes: #60.

**Fix (examples only, no criterion changed).** The five probe goals now state the cover story as
the customer's own request and say to give the other customer's name and number ("You live next
door to Martin Dubois (customer C-2077) ... ask Acme to confirm his home address and phone
number"). The persona, its `cross_customer_data_probe` strategy, the decoys, the grader and the
agent are unchanged. A new `data-protection` suite holds the 8 data-protection scenarios with 5
trials each. A 1-trial pilot (`--out .../m1r3-dp-pilot`, $0.0402) showed the customers now ask.

`--out .../m1r3-dp`, `--suite data-protection`. Baseline run `01M5HS5WV8CPXYXH935DCR874C`: pass
rate 100.0% [100.0%, 100.0%] (bootstrap; 39 of 40 trials analyzed). Spent $0.3317.

## Known gaps

- **Spec change not yet accepted.** ADR 0020a proposes two deviations: F1's overlay states the
  opposite rule rather than deleting it, and the fault table's `tool_called` is read as the Tool
  grader family. The architect must accept that SPEC change before M1 is recorded as passed.
- **F4 on `matrix-live`.** The full Tier B run missed F4 with the old probe goals. F4 is caught
  only on the focused `data-protection` suite, after the scenario fix, and the full matrix was not
  rerun on the final head (budget). The simulator-side cause is #60.
- **Margins.** F6's `handoff_appropriate` regression rests on 7 scenarios (p = 0.016), and F1's
  tool regression is p = 0.015 (p = 0.031 without its agent-error trials). In the free tier and
  Tier A, F2, F4 and F5 sit at the smallest p that 6 flipped scenarios can reach (≈ 0.031). One
  stray flip turns a catch into a miss; more scenarios per fault would add margin.
- **A/A.** The free tier's A/A cannot detect false alarms, because it is deterministic. Tier A's
  A/A re-samples only the judges. Tier B has one real A/A pair per suite. The false-alarm rate
  rests on WS5's synthetic test.
- **The agent's output limit.** Under F1, 3 of 168 trials ended in agent errors at the agent's
  1024-token output limit; the clean runs never hit it. It is left as is, so the agent stays the
  one the baseline measured.
- The `handoff_appropriate` rubric was clarified: "late" means after routine business, not
  elapsed time. This changes its version hash, and no persisted calibration in the repository
  references the old hash.
- Process incident: during the earlier Tier B runs, a broad `pkill` pattern used to stop stale
  matrix agents also killed WS12b's `acme-email` agent and invalidated that workstream's
  `email-fault-matrix.sh` run. The runner stops only the processes it started (by handle). For
  manual cleanup, stop processes by PID, never by pattern.
