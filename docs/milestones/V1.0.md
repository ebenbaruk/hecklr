## Known gaps

None of these is a v1.0 criterion. Each one is recorded so nobody mistakes it for done.

- **SC4 over WebRTC is a release check, not a per-merge one.** The two WebRTC transports
  (LiveKit, SmallWebRTC) are asserted by `scripts/sc4-webrtc.sh` on an idle machine before a
  release (18 passed at load 3.9, PR #129); the per-merge gate skips them on a shared CPU
  ([ADR 0024-hvoice](../adr/0024-hvoice-webrtc-sc4.md), [M2](M2.md)).
- **What ADR 0024 accepted.** SC7's κ values are agreement with AI-drafted labels, not human
  ones. SC3 was measured on 10 cores, not 8. The benchmark rows are preliminary.
- **Evidence that predates the statistics fix.** PR #120 changed how Δ is computed for
  all-or-nothing suites (#98). Every M1/M2 interval printed before it was computed the old way.
  The verdicts are not affected, because they rest on the permutation p-value. On this report's
  tree, a deterministic agent on a small suite now gets INCONCLUSIVE (exit 2) where it used to
  get NO CHANGE.
- **Fault coverage that is not automated.** F10, the voice CLI matrix (F7-F10 through
  `hecklr run`) and the live tiers are not in any automated job. Only F1-F6 (free tier) and
  F7-F9 (scripted) run on every merge.
- **The local gate.** It runs on one macOS laptop shared with other work, so Linux-only failures
  can slip through (ADR 0022a). Timing steps can fail under host load (#121, #123); the gate's
  rule is to rerun them alone and report both results.
- **Nothing is published.** No PyPI package, no hosted docs site, no leaderboard, no launch posts,
  and the `good first issue` label has no open issues until launch day (#111, [LAUNCH](LAUNCH.md)).
